## Context

Graphos already supports project-local agent scaffolding via `graphos init --agents <TARGETS>`. That command creates assistant-specific files inside the current project (e.g., `.opencode/skills/graphos/SKILL.md` and `.opencode/agent/graphos-navigator.md`). However, opencode v1.15.13 loads skills from the user-level `~/.agents/skills/` directory and expects a YAML `name`/`description` frontmatter block. The current generated skill files lack both the right location and the right format, so they are invisible to opencode unless the user manually moves and edits them.

This change adds a dedicated `graphos install-skill --target opencode` command that performs a global, user-level install. It produces two complementary skills — a full `graphos` skill and a read-only `graphos-query` skill — and also updates the project-local skill templates to include YAML frontmatter so they remain loadable if opencode later scans project directories.

## Goals / Non-Goals

**Goals:**
- Add a top-level `install-skill` CLI command with a required `--target` option.
- For `opencode`, install two skills into `~/.agents/skills/`: `graphos` (full) and `graphos-query` (read-only).
- Ensure every generated skill file starts with a YAML `name`/`description` frontmatter block followed by the existing version stamp.
- Keep the install idempotent and non-destructive (skip existing files, exit 0).
- Keep all planning pure (Domain/UseCase); all filesystem effects live in Infrastructure.
- Verify via golden tests that global install output and updated project-local output match expectations.

**Non-Goals:**
- Do not change the behavior of `graphos init --agents` beyond adding frontmatter.
- Do not generate global sub-agent/agent files; opencode agent registration remains project-local.
- Do not add new Haskell dependencies beyond existing parser/text/YAML usage.
- Do not support non-opencode targets in `install-skill` in this cycle.

## Decisions

### 1. Reuse and extend the existing scaffold pipeline rather than introduce a new subsystem
The existing `Scaffold` UseCase already knows how to render skill/agent templates from a command reference and produce a list of pure file plans. We extend it with a new `InstallSkillRequest` target set and new templates for global opencode skills.

**Alternatives considered:**
- A separate standalone module for `install-skill`. Rejected: it would duplicate command-reference rendering, frontmatter logic, and golden-test patterns already present in `Scaffold`.

### 2. Keep target validation in the CLI parser with a closed enum
`--target` uses an `optparse-applicative` bounded enum (e.g., `InstallSkillTarget = OpencodeTarget`) so invalid targets are rejected before any planning occurs, matching `init --agents` behavior.

**Alternatives considered:**
- Free text target with runtime validation. Rejected: gives worse error messages and prevents the parser help from listing valid targets.

### 3. Resolve `~/.agents/skills/` in Infrastructure, not UseCase
The UseCase planner emits a file plan whose relative path is rooted at a configurable base directory. The Infrastructure layer resolves that base to `getHomeDirectory </> ".agents" </> "skills"` and performs the writes. This preserves architecture purity.

**Alternatives considered:**
- Passing an absolute home-derived path into UseCase. Rejected: UseCase must remain pure and IO-free.

### 4. Frontmatter is injected as a single template helper
All skill templates (project-local and global) share a `skillFrontmatter :: Text -> Text -> Text` helper that produces the `---\nname: ...\ndescription: ...\n---\n` block, followed by the existing `generated by graphos ...` stamp. This keeps the change localized and avoids duplicating YAML formatting logic across templates.

**Alternatives considered:**
- Embedding frontmatter manually in each template. Rejected: fragile and easy to drift between templates.

### 5. Global query-only skill forbids maintenance in its prose, not via parser flags
`graphos-query` is a markdown skill consumed by the LLM. Its safety model is instructive: the skill body explicitly says it must not run build/update/ingest commands. There is no runtime enforcement because opencode skills are static prompts.

**Alternatives considered:**
- Exposing a restricted command set to the model. Rejected: opencode skill content is the only lever we have; the parser is unchanged.

### 6. No agent files for global install
`install-skill` writes only `SKILL.md` files. The `~/.agents/agents/` directory is not touched because opencode registers agents relative to a project workspace.

**Alternatives considered:**
- Creating a global `graphos-navigator` agent. Rejected: based on environment observation, opencode agent discovery is project-local.

## Risks / Trade-offs

- **[Risk] opencode skill-loading format changes in a future release.** → Mitigation: frontmatter is standard YAML and the version stamp remains; a follow-up PDCA cycle can adjust the block if opencode changes requirements.
- **[Risk] Tests for global install touch the real home directory.** → Mitigation: the Infrastructure writer accepts an output root; tests inject a temporary directory, while production uses `getHomeDirectory`.
- **[Risk] Project-local golden files need regeneration after frontmatter addition.** → Mitigation: include updated golden files in the same change and run `cabal test` before commit.
- **[Risk] Two similar skills drift out of sync.** → Mitigation: both templates live in the same module and share command-reference/frontmatter helpers.

## Verification Strategy (Check)

- `cabal build` with `--flag dev` must produce zero warnings.
- `cabal test` must pass, including:
  - New golden-file tests for `install-skill --target opencode` (both skill files, idempotency, skip messages).
  - Updated golden-file tests for `graphos init --agents opencode` project-local skill now containing frontmatter.
  - Existing parser-reference tests still pass; skill command references remain parser-derived.
- Manual check: generated files start with `---\nname: ...\ndescription: ...\n---\n` followed by `generated by graphos ...`.
- Manual check: second run of `graphos install-skill --target opencode` skips both files and exits 0.

## Iteration & Rollback (Act)

If `cabal test` fails, fix the template/output mismatch in the same cycle. If the generated files still do not appear in opencode's `available_skills`, verify whether additional registration (e.g., `package.json` manifest, `npx skills` indexing, or a model restart) is required and document findings in a follow-up proposal. If global skills fully replace the need for project-local scaffolding, deprecate `init --agents` in a future cycle rather than deleting it immediately.
