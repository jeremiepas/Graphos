## Why

The Graphos `graphos init --agents opencode` command scaffolds a project-local skill at `.opencode/skills/graphos/SKILL.md`, but opencode (v1.15.13 in this environment) registers skills from the user-level `~/.agents/skills/` directory and expects a YAML `name/description` frontmatter block. The current generated skill has neither the right location nor the right format, so it never appears in the model's `available_skills` list and is effectively invisible. The user wants a one-time global install that produces a loadable opencode skill, plus a separate query-only skill for read-only graph exploration.

## What Changes

- **Add `graphos install-skill --target <TARGET>` command** (PRD §13.1 extension). Target `opencode` installs skills into the user-level `~/.agents/skills/` directory. This is a deliberate global-install action, distinct from project-local `graphos init`.
- **Generate two opencode global skills** when target is `opencode`:
  - `~/.agents/skills/graphos/SKILL.md` — broad skill covering graph query, maintenance (`--update`, `ingest`), and build operations.
  - `~/.agents/skills/graphos-query/SKILL.md` — query-only skill covering `query`, `path`, `explain`, `symbols`, and `neighbors`. It explicitly forbids build/update/ingest operations.
- **Add YAML frontmatter to all generated skills** (`name`, `description`) so opencode actually registers them. The existing `generated by graphos <version>` stamp remains immediately after the frontmatter.
- **Leave `graphos init --agents opencode` unchanged** for project-local scaffolding (`.opencode/skills/graphos/SKILL.md` + `.opencode/agent/graphos-navigator.md`), but ensure its generated skill also receives the new YAML frontmatter so it is loadable if opencode later scans that directory.
- **No global sub-agent** is generated: opencode's agent registry appears project-local, so `install-skill` only produces skills, not agents.

## Capabilities

### New Capabilities
- `global-agent-skill-install`: Install user-level AI assistant skills outside the repo via a dedicated CLI command, with target-specific paths and optional variants (`graphos` vs `graphos-query`).

### Modified Capabilities
- `agent-scaffolding`: Generated skill files MUST include a valid YAML frontmatter block with `name` and `description` before the version stamp, so they are registered as loadable skills by opencode and similar assistants.

## Impact

**Code**:
- `src/Graphos/UseCase/Scaffold.hs` — add templates/frontmatter for `opencodeGlobalSkill`, `opencodeGlobalQuerySkill`; refactor `opencodeSkillTemplate` to inject frontmatter.
- `src/Graphos/CLI/Parser.hs` — add `install-skill` subcommand with `--target` option.
- `src/Graphos/Infrastructure/Scaffold/Writer.hs` (or equivalent) — add writer that resolves `~/.agents/skills/` path and respects the non-destructive contract.

**Tests**:
- New golden-file tests for `install-skill --target opencode` output.
- Updated existing golden files for project-local skills now that frontmatter is prepended.

**User environment**:
- `~/.agents/skills/graphos/SKILL.md` and `~/.agents/skills/graphos-query/SKILL.md` created on first run of `graphos install-skill --target opencode`. Existing files are skipped (idempotent, non-destructive, same contract as `init`).

**APIs/Dependencies**: No new Haskell dependencies beyond existing `optparse-applicative` and `yaml`/`text` usage.

**Systems**: No runtime system change. Generated files are static markdown consumed by opencode.
