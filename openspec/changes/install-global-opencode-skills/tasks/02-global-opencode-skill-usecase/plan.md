# Task 2 — Extend scaffold UseCase with global opencode skill planning — PLAN

**Task slug**: `02-global-opencode-skill-usecase`
**Attempt**: 1
**Status**: pending

## Summary

Add a pure planner in the UseCase/Scaffold module that, given a global-install request and a command reference, returns two file plans: the full `graphos` skill and the read-only `graphos-query` skill.

## Detail

### Scope
- Introduce `InstallSkillRequest` type carrying the target.
- Add `installSkillPlan :: InstallSkillRequest -> CommandReference -> [FilePlan]` in UseCase/Scaffold.
- Add global skill templates `opencodeGlobalSkillTemplate` and `opencodeGlobalQuerySkillTemplate`.
- Create a shared `skillFrontmatter` helper that renders YAML `name`/`description` and the version stamp.
- Ensure both global skills include a parser-derived command reference.

### Check Criteria (defined before code)
- C1: `installSkillPlan OpencodeTarget` returns exactly two `FilePlan` values.
- C2: Relative paths are `graphos/SKILL.md` and `graphos-query/SKILL.md` under a configurable global skills root.
- C3: Both plans' content begins with `---\nname: ...\ndescription: ...\n---\n` followed by `generated by graphos ...`.
- C4: The `graphos-query` plan content contains an explicit statement forbidding build, update, and ingest operations.
- C5: The `graphos` plan content permits build/update/ingest (or delegates to existing full-skill prose).
- C6: Unit test with a fixed `CommandReference` passes and produces deterministic output.

### Affected Modules
- `src/Graphos/UseCase/Scaffold.hs`
- Possibly `src/Graphos/Domain/Scaffold.hs` or similar domain types

### Prerequisites
- Task 1 completed (so the request type is defined) is ideal but not strictly blocking for pure planner work.

### Risks
- Templates could drift from project-local skill content. Mitigation: share the command-reference renderer and frontmatter helper.
