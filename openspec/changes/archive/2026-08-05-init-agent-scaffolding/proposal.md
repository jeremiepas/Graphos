# Proposal: init-agent-scaffolding

## Why

Graphos builds a queryable knowledge graph, but the AI agents that would benefit most (opencode, Claude Code) only use it if someone hand-writes a skill file and wires it into their agent config. Today that integration lives outside the tool as manually maintained files (e.g. `~/.config/opencode/skills/graphos/SKILL.md`), which:

- Makes graphos invisible to agents in freshly initialized projects — the graph exists but nothing tells the agent to query it instead of grepping.
- Goes stale silently: the hand-written skill documents CLI flags and caveats that drift as the CLI evolves (PRD §13 CLI Reference).
- Doesn't scale across agent runtimes (opencode vs Claude Code vs generic `.agents/` convention).

`graphos init` (PRD §13.1) already scaffolds project configuration (`graphos.yaml`, PRD §14). Extending it to scaffold agent integration makes graphos self-installing into the AI tooling of any project.

## What Changes

- `graphos init` gains an agent-scaffolding step (opt-in flag `--agents [targets]`) that generates:
  - A **skill** (`SKILL.md`) teaching the primary agent when/how to use `graphos query|path|explain|ingest`, when to build vs `--update`, and the decision flow (graph-first, grep as fallback).
  - A **sub-agent** definition (graph navigator/builder): tool-restricted markdown agent allowed to run `graphos` commands — including `graphos . --update`, full builds, and `graphos ingest` on new files — but not to edit project code.
- **Targets: all three formats** from one embedded template set:
  - opencode: `.opencode/skills/graphos/SKILL.md` + `.opencode/agent/graphos-navigator.md`
  - Claude Code: `.claude/skills/graphos/SKILL.md` + `.claude/agents/graphos-navigator.md`
  - Generic: `.agents/graphos.md` (portable convention, single file)
- **Self-documenting command reference**: the command/flag reference section of the generated skill is rendered from the optparse-applicative parser at generation time, so scaffolded docs can never document flags that don't exist.
- Idempotent, same politeness as `graphos.yaml`: never overwrite existing files; print what was created/skipped; generated files carry a version stamp (`generated by graphos <version>`).
- `graphos init` without the flag prints a hint that `--agents` exists (discoverability without surprise files).

Out of scope (future work): MCP registration (editing user `opencode.json`/`.mcp.json` is riskier than dropping new files), auto-refresh of stale scaffolds.

## Capabilities

### New Capabilities
- `agent-scaffolding`: Generation of agent skill and sub-agent definition files for opencode, Claude Code, and generic `.agents/` targets during `graphos init --agents`, including template embedding, target selection/detection, idempotent file writes, and parser-derived command reference.

## Impact

- **Code**: `app/Main.hs` (CLI option parsing for `init --agents`, help rendering); new Infrastructure module(s) for template rendering + file writing (all IO in Infrastructure per architecture-purity); pure template/target logic in Domain/UseCase.
- **Docs**: PRD §13.1 command table (`graphos init --agents`); README init section; a workflow doc for agent scaffolding.
- **Dependencies**: none new expected (`file-embed` or plain string templates; optparse-applicative help already available).
- **Sequencing**: MUST land after `improve-query-agent-ergonomics` (in flight) — the skill template documents the query CLI contract that change is redefining. Template content is written against the post-ergonomics CLI.

## PDCA Cycle

- **Plan**: Hypothesis — projects scaffolded with `--agents` get agents that answer codebase questions via `graphos query` instead of grep, with zero manual setup. Success (PRD §16): scaffolding adds negligible runtime to init; generated files are valid for their target runtimes; no flag mentioned in generated skill is absent from the real parser.
- **Do**: Implement `agent-scaffolding` per specs/design: embedded templates, target writers, parser-derived reference, idempotent init flow.
- **Check**: Hspec tests — golden tests for each target's generated files; property/consistency test that every flag string in the generated reference exists in the parser help; idempotency test (second run skips, never overwrites); manual verification that opencode and Claude Code load the generated skill/sub-agent.
- **Act**: If formats drift (opencode/Claude Code frontmatter changes), fold fixes into templates and stamp new version; feed learnings into a future `graphos agents update`/MCP-registration cycle.
