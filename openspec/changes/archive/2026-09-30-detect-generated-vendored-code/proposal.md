## Why

A single machine-generated file (~350k lines of `rust-bindgen` output) produced
~61,000 nodes that collapsed into one Leiden community of 32k–43k nodes — 24–33%
of a 132k-node graph. This degenerate mega-community destroys clustering quality,
dominates all centrality metrics (`god_nodes` become `DWORD`, `HRESULT`,
`Option`), and causes MCP query timeouts. Generated and vendored code adds noise
without adding navigational value.

## What Changes

- Add a **detection pass** (in the Detect stage) that classifies files as
  generated, vendored, or minified before extraction.
- Detected files are **excluded by default**, or optionally **collapsed** to a
  single representative node with a child-count attribute.
- Detection signals: generator header comments (e.g. `automatically generated by`),
  well-known vendor directories (`vendor/`, `node_modules/`, `third_party/`),
  and single-line files exceeding a length threshold (minified assets).
- Add config keys and CLI flags to tune thresholds and switch between
  exclude/collapse behavior.
- Emit an INFO summary: `Detected N generated/vendored files (excluded M, collapsed K)`.

## Capabilities

### New Capabilities
- `generated-code-detection`: classify files as generated/vendored/minified during
  the Detect stage and decide whether to exclude or collapse them before extraction.

## Impact

- **UseCase/Detect** stage gains a classification step (pure).
- **Infrastructure/FileSystem** gains header-sniffing and vendor-path matching.
- **Domain/Config** gains detection thresholds and mode.
- Downstream Cluster/Analyze stages benefit (no code changes required).
- Reduces node/edge counts and eliminates the mega-community root cause.
