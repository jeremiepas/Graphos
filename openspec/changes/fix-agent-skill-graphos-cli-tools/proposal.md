## Why

The Graphos-generated agent and skill files have two problems that cause the agent to misuse tools and use the wrong name:

1. **Wrong skill name — `graphify` shadows `graphos`.** The user-installed global skill at `~/.claude/skills/graphify/SKILL.md` calls itself `graphify`, invokes `/graphify`, writes to `graphify-out/`, and shells out to a **Python** package `graphifyy` (via `uv tool run --from graphifyy python`). It is a different tool entirely. Meanwhile Graphos's own scaffolded skill at `.opencode/skills/graphos/SKILL.md` and `.claude/skills/graphos/SKILL.md` uses the `graphos` CLI and writes to `graphos-out/`. Because the global `graphify` skill is listed in the system prompt's available skills, an agent in this repo can pick the wrong one and run Python `graphify` commands instead of the `graphos` CLI — producing `graphify-out/` artifacts the Graphos pipeline never reads.

2. **The `graphos-navigator` agent does not declare `graphos` CLI as a tool; the stale `explore_graphos.md` agent uses non-existent MCP tools.** `Scaffold.hs` generates `.opencode/agent/graphos-navigator.md` (and the `.claude/` equivalent) with `permissions: bash: allow: [graphos *]`, which is correct, but the agent prose tells the model to "run `graphos query`" without framing `graphos` as a first-class tool the way the skill does — the model can drift to `python`/`grep` to "open the graph". Separately, `.opencode/agent/explore_graphos.md` is a hand-authored (not Scaffold-generated, no `generated by graphos` stamp) agent that instructs the model to call `graphos_query_graph`, `graphos_get_node`, etc. — **MCP tools that are not registered in this environment** (the system prompt's tool list has no `graphos_*` MCP tools, only `bash`, `read`, `grep`, etc.). An agent following `explore_graphos.md` will try to call MCP tools that do not exist and fail.

The user-visible symptom: the agent tries to open the graph with Python (`$(cat graphify-out/.graphify_python)`) or calls `graphos_*` MCP tools, instead of running the `graphos` CLI (`graphos query`, `graphos path`, `graphos explain`, `graphos neighbors`, `graphos symbols`, `graphos ingest`) that this repo actually provides.

## What Changes

- **Update the `graphos-navigator` agent template** (`opencodeNavigatorProse` / `claudeNavigatorProse` in `Scaffold.hs`) to explicitly frame `graphos` as the agent's primary toolset: list the `graphos` subcommands as the tools the agent uses, state that the agent MUST use the `graphos` CLI (not Python, not `graphify`, not MCP tools), and name the output directory `graphos-out/` (not `graphify-out/`). Keep the existing `permissions: bash: allow: [graphos *]` frontmatter (it is already correct).
- **Update the `graphos` skill template** (`opencodeSkillProse` / `claudeSkillProse` / `genericProse` in `Scaffold.hs`) to add a short "Tool: graphos CLI" section that explicitly says the skill is driven by the `graphos` binary (not Python, not MCP), points to `graphos-out/graph.json` as the graph location, and warns against confusing it with the unrelated `graphify` Python tool.
- **Remove the stale, non-generated `.opencode/agent/explore_graphos.md`** (it references MCP tools that are not registered here). It is not produced by `Scaffold.hs` (no `generated by graphos` stamp, not in `targetFiles`), so it is a manual artifact that contradicts the scaffolded `graphos-navigator`. Deleting it removes the MCP-tool misdirection. (If MCP tools are later registered, a separate change can re-introduce an MCP-mode agent.)
- **Regenerate** the scaffolded files in this repo (`.opencode/skills/graphos/SKILL.md`, `.opencode/agent/graphos-navigator.md`) by re-running `graphos init --agents opencode` (idempotent — the spec's non-destructive rule means existing files are skipped; this change will move the existing files aside first, then regenerate, or use a `--force` path if the scaffold lacks one — see design).
- **Rename the global skill from `graphify` to `graphos`.** The user-installed global skill at `~/.claude/skills/graphify/SKILL.md` calls itself `graphify`, invokes `/graphify`, and writes to `graphify-out/`. It is the wrong name — the tool is `graphos`. Rename the directory `~/.claude/skills/graphify/` → `~/.claude/skills/graphos/`, update the skill's `name:` frontmatter to `graphos`, change the trigger `/graphify` → `/graphos`, and change `graphify-out/` → `graphos-out/` throughout. Update `~/.claude/CLAUDE.md` to reference `~/.claude/skills/graphos/SKILL.md` and the `/graphos` trigger. This is a user-environment file (outside the repo) and is touched as a one-time rename, not via the scaffold.

### Modified Capabilities
- `agent-scaffolding`: The generated sub-agent and skill files SHALL explicitly declare the `graphos` CLI as the agent's toolset (subcommands listed), SHALL name `graphos-out/` as the output directory, and SHALL instruct the agent to use the `graphos` CLI rather than Python, `graphify`, or MCP tools.
